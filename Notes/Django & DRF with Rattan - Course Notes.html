Part 1: Django Fundamentals & Project Setup

1. What is Django?

Definition: Django is a high-level Python web framework that enables rapid development of secure and maintainable websites.

Key Points:

  • Follows MVT (Model-View-Template) architecture
  • Comes with built-in admin panel
  • Includes ORM (Object-Relational Mapping)
  • Battery-included philosophy - provides authentication, sessions, messages, etc. out of the box

Why Django?

  • Fast development
  • Less code required
  • Built-in security features
  • Scalable for large applications

2. MVT Architecture Explained

MVT = Model-View-Template

ComponentResponsibility
ModelDatabase operations, data structure
ViewBusiness logic, request handling
TemplatePresentation layer (HTML)

Request Flow:

User → URL → View → Model (if DB needed) → View → Template → Response to User

Important: Model never directly talks to Template or User. View acts as the mediator.

9. Models - Database Tables

Creating a Model:

from django.db import models

class Department(models.Model):
    name = models.CharField(max_length=25)
    location = models.CharField(max_length=25)

    def __str__(self):
        return f"{self.name} - {self.location}"

class Employee(models.Model):
    first_name = models.CharField(max_length=50)
    last_name = models.CharField(max_length=50)
    email = models.EmailField(unique=True)
    designation = models.CharField(max_length=50)
    salary = models.IntegerField()
    joining_date = models.DateField()
    is_active = models.BooleanField(default=True)
    image = models.ImageField(upload_to='employees/', default='default.png')

    # Foreign Key (Many-to-One)
    department = models.ForeignKey(
        'Department',
        on_delete=models.SET_NULL,
        null=True,
        blank=True
    )

    # Self-referencing Foreign Key
    manager = models.ForeignKey(
        'self',
        on_delete=models.SET_NULL,
        null=True,
        blank=True
    )

    def __str__(self):   # member function
        return f"{self.first_name} {self.last_name}"
    
    def full_name(self):  # virtual field
		    return f"{self.first_name} {self.last_name}"

Common Field Types:

Field TypeUse Case
CharFieldShort text (requires max_length)
TextFieldLong text
IntegerFieldNumbers
EmailFieldEmail addresses
DateFieldDates
BooleanFieldTrue/False
ImageFieldImages (requires Pillow)
ForeignKeyMany-to-One relationship

Field Options:

OptionPurpose

unique=TrueNo duplicates allowed
null=TrueAllow NULL in database
blank=TrueAllow empty in forms

on_delete Options:

  • when you change the model you have to run migrations, not when you change in method / member functions.

Flow:

def login_view(request):
    if request.user.is_authenticated:
        return redirect('home')

    if request.method == 'POST':
        form = AuthenticationForm(request, data=request.POST)
        if form.is_valid():
            user = form.get_user()
            login(request, user)
            return redirect('home')
    else:
        form = AuthenticationForm()
    return render(request, 'login.html', {'form': form})

1. Introduction to APIs and REST

1.1 What is an API?

API (Application Programming Interface): A two-way communication bridge between frontend and backend.

  • Client: Mobile app, React app, etc.
  • Server: Django backend
  • API: Middleman that carries requests and responses

Analogy: Restaurant – you (client) → waiter (API) → kitchen (server)

1.2 What is REST?

REST (Representational State Transfer): A set of principles for building APIs.

Key Principles:

  • Stateless: Server doesn't store client state between requests
  • Client-Server: Separation of concerns
  • Uniform Interface: Standard methods (GET, POST, PUT, DELETE)
  • JSON/XML: Standard data formats

1.3 HTTP Methods

MethodPurpose
GETRetrieve data
POSTCreate new data
PUTUpdate existing data
DELETEDelete data

1.4 JSON Format

{
    "id": 1,
    "name": "John Doe",
    "email": "john@example.com"
}
  • Key-value pairs
  • Double quotes required
  • Similar to Python dictionary

4.2 GET & POST (List & Create)

from rest_framework.decorators import api_view
from rest_framework.response import Response
from rest_framework import status
from students.models import Student
from .serializers import StudentSerializer

@api_view(['GET', 'POST'])
def StudentView(request):
    if request.method == 'GET':
        students= Student.objects.all()
        serializer = StudentSerializer(students, many=True)
        return Response(serializer.data, status=status.HTTP_200_OK)

    elif request.method == 'POST':
        serializer = StudentSerializer(data=request.data)
        if serializer.is_valid():
            serializer.save()
            return Response(serializer.data, status=status.HTTP_201_CREATED)
        return Response(serializer.errors, status=status.HTTP_400_BAD_REQUEST)

4.3 GET, PUT, DELETE (Detail)

from django.shortcuts import get_object_or_404

@api_view(['GET', 'PUT', 'DELETE'])
def StudentDetailView(request, pk):
    student = get_object_or_404(Student, pk=pk)

    if request.method == 'GET':
        serializer = StudentSerializer(student)
        return Response(serializer.data, status=status.HTTP_200_OK)

    elif request.method == 'PUT':
        serializer = StudentSerializer(Student, data=request.data)
        if serializer.is_valid():
            serializer.save()
            return Response(serializer.data, status=status.HTTP_200_OK)
        return Response(serializer.errors, status=status.HTTP_400_BAD_REQUEST)

    elif request.method == 'DELETE':
        Student.delete()
        return Response(status=status.HTTP_204_NO_CONTENT)

Key Points:

  • @api_view decorator required
  • request.data for incoming data
  • serializer.data for outgoing data
  • Always return status codes

5.1 List & Create

from rest_framework.views import APIView
from rest_framework.response import Response
from rest_framework import status

class EmployeesView(APIView):
    def get(self, request):
        employees = Employee.objects.all()
        serializer = EmployeeSerializer(employees, many=True)
        return Response(serializer.data, status=status.HTTP_200_OK)

    def post(self, request):
        serializer = EmployeeSerializer(data=request.data)
        if serializer.is_valid():
            serializer.save()
            return Response(serializer.data, status=status.HTTP_201_CREATED)
        return Response(serializer.errors, status=status.HTTP_400_BAD_REQUEST)

5.2 Detail (GET, PUT, DELETE)

class EmployeeDetailView(APIView):
    def get_object(self, pk):
        return get_object_or_404(Employee, pk=pk)

    def get(self, request, pk):
        employee = self.get_object(pk)
        serializer = EmployeeSerializer(employee)
        return Response(serializer.data, status=status.HTTP_200_OK)

    def put(self, request, pk):
        employee = self.get_object(pk)
        serializer = EmployeeSerializer(employee, data=request.data)
        if serializer.is_valid():
            serializer.save()
            return Response(serializer.data, status=status.HTTP_200_OK)
        return Response(serializer.errors, status=status.HTTP_400_BAD_REQUEST)

    def delete(self, request, pk):
	        employee = self.get_object(pk)
        employee.delete()
        return Response(status=status.HTTP_204_NO_CONTENT)

6. Mixins and Generics ( use for common crud operations)

Mixins are reusable code classes in object-oriented programming that provide reusable built-in functionality for common CRUD operations. In RDF, mixins are used to add common functionality to views. i.e .list(), .create(), update(), delete().

6.1 Available Mixins

MixinProvideswhat it do
ListModelMixin.list()list of objects
CreateModelMixin.create()
RetrieveModelMixin.retrieve()return single instance
UpdateModelMixin.update()
DestroyModelMixin.destroy()

6.2 GenericAPIView

mixins only work with GenericAPIView. generics will come with request methods i.e get, post, put, delete

class Employees(mixins, generics.GenericAPIView)

get( ), post( ), put ( ), delete( )

Provides:

  • queryset attribute
  • serializer_class attribute
  • get_object() method

brief note:

mixins will come with mixins classes and generics will come with request methods and provide views.

6.3 Example: List & Create

from rest_framework import mixins, generics

class EmployeesView(mixins.ListModelMixin,
                    mixins.CreateModelMixin,
                    generics.GenericAPIView):
    queryset = Employee.objects.all()
    serializer_class = EmployeeSerializer

    def get(self, request):
        return self.list(request)

    def post(self, request):
        return self.create(request)

6.4 Example: Detail (Retrieve, Update, Destroy)

class EmployeeDetailView(mixins.RetrieveModelMixin,
                         mixins.UpdateModelMixin,
                         mixins.DestroyModelMixin,
                         generics.GenericAPIView):
    queryset = Employee.objects.all()
    serializer_class = EmployeeSerializer

    def get(self, request, pk):
        return self.retrieve(request, pk)

    def put(self, request, pk):
        return self.update(request, pk)

    def delete(self, request, pk):
        return self.destroy(request, pk)

6.5 Even Shorter: Generic Classes

DRF provides pre-built generic classes that combine mixins:

ListAPIView —> For listing the objects

CreateAPIView —> For creating the objects

RetrieveAPIView —> For retrieving a single object using pk

UpdateAPIView —> For updating a single object using pk

DestroyAPIView —> For deleting an object using pk

ListCreateAPIView —> For listing and creating objects

RetrieveUpdateAPIView —> For retrieving & updating objects using pk

RetrieveUpdateDestroyAPIView —> For retrieving, updating & deleting objects using pk

from rest_framework import generics

# List + Create
class EmployeesView(generics.ListCreateAPIView):
    queryset = Employee.objects.all()
    serializer_class = EmployeeSerializer

# Retrieve + Update + Destroy
class EmployeeDetailView(generics.RetrieveUpdateDestroyAPIView):
    queryset = Employee.objects.all()
    serializer_class = EmployeeSerializer
    lookup_field = 'pk' #optional / if lookup_field are different name

URLs:

path('employees/', views.EmployeesView.as_view()),
path('employees/<int:pk>/', views.EmployeeDetailView.as_view()),

This is the most concise way to build CRUD APIs!

2. ViewSets (Concept Overview)

2.1 What is a ViewSet?

A ViewSet is a class-based view that provides actions for CRUD operations without defining separate get(), post(), put(), delete() methods. Instead, it provides actions like:

ActionMaps to HTTP Method
list()GET (all)
create()POST
retrieve()GET (single)
update()PUT
partial_update()PATCH
destroy()DELETE
#api/views.py   viewset: allow write all method in single class and
# using router you don't need to write all endpoints url in urls.py 
cass EmployeeViewSet(viewsets.ViewSet):
    def list(self, request):
        employees = Employee.objects.all()
        serializer = EmployeeSerializer(employees, many=True)
        return Response(serializer.data)

    def create(self, request):
        serializer = EmployeeSerializer(data=request.data)
        if serializer.is_valid():
            serializer.save()
            return Response(serializer.data, status=status.HTTP_201_CREATED)
        return Response(serializer.errors)

    def retrieve(self, request, pk):
        employee = get_object_or_404(Employee, pk=pk)
        serializer = EmployeeSerializer(employee)
        return Response(serializer.data, status=status.HTTP_200_OK)

    def update(self, request, pk):
        employee = get_object_or_404(Employee, pk=pk)
        serializer = EmployeeSerializer(employee, data=request.data)
        if serializer.is_valid():
            serializer.save()
            return Response(serializer.data, status=status.HTTP_200_OK)

2.2 ModelViewSet (Most Common) 

from rest_framework import viewsets

class EmployeeViewSet(viewsets.ModelViewSet):
    queryset = Employee.objects.all()

That's it — 3 lines. This handles GET, POST, PUT, PATCH, DELETE automatically.

5. JWT Authentication (Concept Overview)

5.1 What is JWT?

JWT (JSON Web Token): A token-based authentication system for APIs.

  • Access Token: Short-lived (e.g., 5–15 min)
  • Refresh Token: Long-lived (e.g., 7 days)

5.2 Flow

1. User logs in with username/password
2. Server returns Access Token + Refresh Token
3. Client stores tokens
4. Client sends Access Token in Authorization header for each request
5. When Access Token expires, client uses Refresh Token to get new Access Token

5.3 Header Format

Authorization: Bearer <access_token>

5.4 hands-on guide for jwt authentication

1. Installation

Install the package using pip. If you plan to use digital signature algorithms like RSA or ECDSA, install it with the crypto extra: 

pip install djangorestframework-simplejwt[crypto]

2. Configure DRF Settings

Register the plugin as a default authentication class in your settings.py file: 

REST_FRAMEWORK = {
    'DEFAULT_AUTHENTICATION_CLASSES': (
        'rest_framework_simplejwt.authentication.JWTAuthentication',
    )
}

3. Set Up Route Endpoints

Map out the token routes in your project's main urls.py file to handle log-ins and token life cycles.

from django.urls import path
from rest_framework_simplejwt.views import (
    TokenObtainPairView,
    TokenRefreshView,
    TokenVerifyView,
)

urlpatterns = [
    # Login endpoint: Sends username/password -> returns Access & Refresh tokens
    path('api/token/', TokenObtainPairView.as_view(), name='token_obtain_pair'),
    
    # Refresh endpoint: Sends Refresh token -> returns new Access token
    path('api/token/refresh/', TokenRefreshView.as_view(), name='token_refresh'),
    
    # Optional verification endpoint: Validates an existing token
    path('api/token/verify/', TokenVerifyView.as_view(), name='token_verify'),
]

⚙️ Common Configuration Setting

You can customize token behavior by defining a SIMPLE_JWT block in your settings.py. Here is a production-safe baseline.

from datetime import timedelta

SIMPLE_JWT = {
    'ACCESS_TOKEN_LIFETIME': timedelta(minutes=15),   # Short lifespan for security
    'REFRESH_TOKEN_LIFETIME': timedelta(days=7), # Longer lifespan to stay loggedin
    'ROTATE_REFRESH_TOKENS': True,       # Issue a new refresh token on every usage
    'BLACKLIST_AFTER_ROTATION': True,   # Destroys the old refresh token (Requires blacklist app)
    
    'ALGORITHM': 'HS256',
    'AUTH_HEADER_TYPES': ('Bearer',)#Expected header: Authorization: Bearer <token>
}

🔒 Core Features

  • Stateless Authentication: Server-side sessions are not needed, lowering server resource consumption.
  • Token Rotation & Blacklisting: Enables you to safely invalidate stolen tokens immediately by installing the built-in rest_framework_simplejwt.token_blacklist app.
  • Custom Claims: Allows you to effortlessly inject custom user attributes (like is_staff or role) directly into the encoded token payload.

13. Key Takeaways from the Entire Course

13.1 Django Core

  • MVT architecture — Model never talks to Template directly
  • Always use virtual environments
  • Migrations are auto-generated blueprints for the database
  • get_object_or_404 handles missing objects gracefully
  • @login_required protects views
  • Context processors provide user to all templates

13.2 DRF

  • Serialization = model → JSON
  • Deserialization = JSON → model
  • Always return proper HTTP status codes
  • Use many=True when serializing querysets
  • request.data = incoming data
  • serializer.data = outgoing data
  • @api_view decorator is mandatory for function-based API views
  • Use .as_view() for class-based views in URLs

13.3 Choosing the Right Approach

Complex custom logicFunction-Based or APIView
Standard CRUD with some logicMixins + Generics
Pure standard CRUDGeneric Classes or ViewSets
Quick prototypeViewSets + Routers
